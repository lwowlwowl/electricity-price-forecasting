# 16｜完整双结算选模与RT方案冻结

## 当前正式方案

进入F0/F1/F2五来源融合消融时固定：

- RT-at-DA checkpoint：seed 2；
- 滚动RT checkpoint：纯Huber训练的seed 2；
- RT执行：`rt_only`；
- 每小时预测4步，只执行第1步；
- 只有RT实际动作更新真实SOC；
- `u_DA`锁定并进入双结算；
- 不启用偏差罚金，不人为加入期末库存收益。

机器可读配置：`configs/decision_aware/rt_coordination_spread_v2.yaml`。

## 为什么没有换成MPC

4小时约束MPC及其决策感知微调在验证集达到151.18/天，高于正式方案的
148.51/天；但最后一次测试平均只有87.18/天，低于正式方案89.44/天。

因此不能用“验证集赢了”覆盖“测试集没有泛化”的事实。MPC记录在
`configs/decision_aware/rt_coordination_mpc_candidate_v3.yaml`，状态是候选、不晋级。

旧`track_adjust`只有34.13/天，原因是局部切换没有推演后续SOC，已经被覆盖，
不再作为正式策略结论。

## 以后怎样选新的RT方案

1. 只在预先固定的验证期选择模型和策略。
2. 与多个固定DA参考组合，按完整DA+RT双结算收益取平均。
3. 同时报告收益分项、正收益日比例、吞吐成本和SOC轨迹。
4. 测试期只在所有选择完成后查看一次。
5. 这次测试期已经使用；再次修改MPC必须建立新的最终留出期。

## 当前停止位置

正式RT基线已经冻结，可以作为F0/F1/F2中不变的评价条件。MPC研究分支保留，
但不会跟随每组融合实验一起变化，否则无法判断收益变化来自融合还是RT策略。
