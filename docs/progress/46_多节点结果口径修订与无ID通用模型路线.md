# 多节点结果口径修订与无 ID 通用模型路线

> 日期：2026-10-13  
> 这是对第27号及之后多节点文档的统一口径修订，不删除历史结果，也不修改源数据。

## 1. 身份 embedding 从哪里开始

第27号文档《多节点Global年度训练与完整系统》首次把 `node_id` 和 `market_id` 作为可学习 embedding
加入模型。它解决的是：多个已知节点/市场共享一套参数，同时保留节点和市场的系统性差异。

因此从第27号开始，凡配置中有：

```yaml
global_use_entity_embeddings: true
```

的结果都属于“已知实体身份条件化 Global 结果”。这些结果可以回答：

- 已知节点之间共享参数是否有效；
- 已知市场/节点条件化是否提高 ERCOT 收益或预测误差；
- 多节点连续 MPC 和统一结算链是否正确。

但它们不能回答：训练时完全没有见过的第五个市场，是否可以直接输入历史数据并预测。

## 2. 后续结果是不是“不准确”

不是。需要改的是结果的适用范围，而不是把结果全部作废。

### 仍然有效

- 多节点数据合同、时间起报合同、源数据哈希；
- 节点等权/市场等权采样和评价；
- 连续 DA LP、滚动 RT MPC、连续 SOC、偏差罚金和退化成本实现；
- ERCOT 已知15节点上的收益比较；
- 经济状态头在已知 ERCOT 节点上的三seed稳定性；
- 带 ID 模型作为“已知实体条件化上界”或结构消融对照。

### 不能再这样表述

带 ID 的结果不能写成：

- “任意新市场可以直接使用”；
- “模型已经完成零样本跨市场泛化”；
- “不需要目标市场/节点适配”。

原因是 embedding 是训练期实体的查找表。新市场没有对应的已学习向量；即使强行分配一个旧 ID，
也会把错误的市场先验带入预测。

## 3. 最终通用模型的新硬合同

最终部署模型必须满足：

```yaml
global_use_entity_embeddings: false
global_num_nodes: 0
global_num_markets: 0
global_normalization_mode: context_robust
```

`node_id`/`market_id`可以继续存在于数据对象中，但只允许用于：

- 市场等权、节点等权采样；
- 逐市场和逐节点指标汇总；
- SOC 状态隔离；
- 数据审计和结果文件命名。

它们不得进入模型前向、损失、预测或门控。

`context_robust` 归一化只使用当前样本起报前可见的历史窗口，例如中位数/MAD；不能读取目标市场
训练期拟合的节点 scaler。这样新市场无需先注册新的 scaler 或 embedding。

## 5. 最终结论标准

只有当无 ID 三模型在留一市场实验中表现合理，才可以称为“跨这四个美国市场可迁移的通用模型”。
不能据此声称对所有世界市场必然有效；新市场仍需满足相同字段、小时频率、信息发布时间和目标定义。

带 ID 的四市场模型继续保留，作用是已知实体对照上界；它不再是最终通用部署模型。
