# 四市场起报合同与缓存隔离修正

> 日期：2026-10-10  
> 阶段：AutoDL任务专属损失训练期间的本地推进。  
> 状态：已完成实现、本地CUDA smoke和全仓回归；本轮未访问或干扰云端训练。

> **通用性边界修订**：本文的四市场三任务配置使用 node/market embedding，因而是“64 个已知实体的
> 联合模型”，不是任意新市场零样本模型。本文关于采样、起报时刻和缓存隔离的结论仍然有效；但通用
> 模型必须另用无 ID、context-robust 配置并通过留一市场验证。

## 1. 本轮结论

四市场数据和模型前向先前虽然通过smoke，但跨市场数据构造会把主配置的ERCOT
`D-1 10:00`起报时刻静默复制给所有市场。这对NYISO和PJM的DA/RT-at-DA信息边界不正确，
因此原四市场smoke只能证明形状兼容，不能证明时间合同正确。

现冻结为显式的市场本地起报合同：

- CAISO：10:00 Pacific；
- ERCOT：10:00 Central Prevailing Time；
- NYISO：05:00 Eastern；
- PJM：11:00 Eastern。

正式跨市场配置若缺少任一市场的时刻，训练在读取数据前直接失败，不再回退到ERCOT的10:00。

## 2. 缓存污染修正

市场专属基线smoke还暴露了另一个问题：旧NPZ预测缓存的身份不包含DA起报时刻。
即使配置由10:00修改为05:00，也可能复用旧预测。发现后已立即停止批处理，并将缓存合同升级为v2。

新缓存必须同时匹配：

- schema版本；
- 市场、任务、年度阶段、节点和seed；
- DA本地起报小时；
- context长度与DA/RT预测长度；
- 正式合同哈希和实体映射哈希。

任一字段缺失或不匹配都强制重算；旧缓存不再被默认提升为正式结果。

## 3. 跨市场三任务合同

现有三份独立配置：

- `global_multimarket_da_mae_v1.yaml`：DA + MAE；
- `global_multimarket_rt_at_da_pseudohuber_v1.yaml`：RT-at-DA + 伪Huber；
- `global_multimarket_rt_mae_v1.yaml`：滚动RT + MAE。

三者都是自有Transformer，无lag168、无XGBoost输入/残差/教师信号，并共同满足：

- 每轮先等权抽市场，再在市场内等权抽节点；
- checkpoint先在每市场内对节点等权求MAE，再对四市场等权平均；
- 每轮验证显式保存每市场MAE和最差市场MAE，不允许PJM的35个节点掩盖CAISO的3个节点；
- checkpoint元数据保存四个市场的起报时刻。

云端入口`run_cloud_global_multimarket_taskloss_v1.sh`已准备，它固定复用现有
`/root/autodl-tmp/epf-venv/bin/python`，校验四市场源数据哈希，支持断点续训，不创建新环境。

## 4. 外部市场基线准备

CAISO、NYISO和PJM已各有市场专属预测配置，不再用`--market`把ERCOT配置强行覆盖为
其他市场。`run_cloud_multimarket_xgboost_baselines_v1.sh`已准备Seasonal、LEAR和三种XGBoost损失。
三个市场、三个任务的Seasonal基线smoke已在强制废弃旧缓存后通过。

这些smoke每节点只有3个验证样本，数值不参与模型排名。其它ISO的偏差罚金和结算合同仍未冻结，
因此目前只能正式比较价格预测，不能复制ERCOT规则后声称外部市场收益胜出。
