# 现有奥地利数据可执行性审计

> 审计日期：2026-11-05

## 1. 已有数据足够做什么

`data/Austria/奥地利_20250801_20260930.parquet`共有40,896个连续15分钟时段和22列，UTC范围为
`[2025-07-31 22:00Z, 2026-09-30 22:00Z)`。其中日前价格无缺失；评价段覆盖2025-10-01至
2026-09-30共365个当地日。老师记分板的`n=366`比本地多一天。

可以立即执行：

1. 按老师给出的`212.4560 EUR/MWh`阈值构造候选尖峰日，并从真值识别负价日；
2. 在现有冻结模型可产生有效预测的335日上，重算decision-aware、三特征Router和原Transformer的
   全部/负价/尖峰/普通日DA MAE；
3. 在已有完整RT结算数据的335日上复核现有双结算结果；
4. 建立接收团队逐时预测后即可运行的统一MAE和DA结算器。

## 2. 为什么仍需要团队逐时预测

现有Parquet只有市场真值和本项目所需的原始观测，不包含BRIM、TimesFM3、Chronos2、LGBM32等
老师记分板模型的逐15分钟预测。聚合MAE不能反推出每个时段的预测，因此不能用于：

- 在统一日期交集上重新计算公平MAE；
- 计算逐日配对区间；
- 运行储能优化和结算；
- 分解负价日、尖峰日的经济贡献。

所以335日或365日共同交集不需要再索取奥地利DA真值，但仍必须索取各团队模型的逐时预测和覆盖
掩码；若必须逐字复现老师的366日原表，还需要补充2026-10-01最后一日真值。

## 3. 为什么不能仅凭现有字段复现32维模型

当前22列包含DA价格、实际负荷、实际风光、日历、实际天气和不平衡结算价格。它不包含交接方案所需的
门控前负荷/风光/总发电DA预报、TTF、MaxBex及12路分电源实发lag24等完整字段。

实际负荷、实际风光和实际天气若直接作为未来交付日协变量，会造成日前信息泄漏。它们只能作为已完成
历史进入模型，不能替代门控前可知的DA预报。因此可以直接评价已有冻结模型，但不能据此声称已经复现
老师的TimesFM3、Chronos2或LGBM32特征工程模型。

## 4. 结算区间限制

2026年9月共有2,880个15分钟点缺少不平衡最终结算价格。因此：

- 本地DA真值足够评价365日；老师的366日表还多一个普通日；
- 本项目冻结模型依赖历史RT输入，目前有效共同区间仍为335日，不能用缺失RT静默补值来凑满366日；
- 依赖RT/不平衡价格的完整双结算仍只能使用截至2026-09-01的335日，除非补齐并审计9月数据；
- 不能把365/366日DA分数与335日完整收益写成同一覆盖范围。

## 5. 与老师分组的复核

采用“先判负价；非负价日再判是否超过`212.4560`；其余为普通日”的互斥规则，本地365日得到：

- 负价日63；
- 尖峰日112；
- 普通日190。

老师为`63/112/191`，负价与尖峰计数完全相同，仅多一个普通日。这与老师额外包含2026-10-01的
解释一致，也说明分组优先级已经可以在本地可靠复现。
