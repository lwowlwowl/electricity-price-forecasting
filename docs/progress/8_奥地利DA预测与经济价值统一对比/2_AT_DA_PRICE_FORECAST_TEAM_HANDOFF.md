## 1. 任务定义

### 1.1 市场与目标

- **市场**：奥地利（Austria）日前电价（Day-Ahead）。  
- **目标变量**：每个 delivery 时刻的日前出清价（€/MWh）。  
- **分辨率**：工程上可做 **小时** 或 **15 分钟**；特征逻辑相同，对齐时注意一天 24 vs 96 点。  
- **预测时点**：在 **D 日门控前**，预测 **D+1 日** 全天价格轨迹（不是用 D+1 实发去“预测”D+1 价）。

### 1.2 为什么要单独做 AT

奥地利价由 **净需求（负荷−风光）**、**水电/抽蓄**、**与德国等耦合**、**燃料成本（气）** 共同驱动。  
特征工程必须同时满足：**门控前可知**、**外推有效**（不是训练集上 Gain 高就算数）。

### 1.3 推荐基线模型（团队默认）


| 层级      | 建议                                   |
| ------- | ------------------------------------ |
| 地板      | 昨同小时价（`price_lag24`）                 |
| **主路径** | **LightGBM**（点预测或分位均可；特征用下文 32 维）    |
| 对照      | 稀疏线性 / LEAR 类（特征宜更少，约 16 维辅集，勿塞满候选库） |
| 可选增强    | 预训练时序基础模型（见 §8）；**特征取舍与树模型不完全相同**    |

## 2. 信息集（防泄漏硬规则）

做日前预测时，按「门控前能否合法知道」分类：


| 类型             | 规则                                      | 例子                                                                         |
| -------------- | --------------------------------------- | -------------------------------------------------------------------------- |
| **日前可知（可用当期）** | 门控前已发布的预报 / 日历 / 容量代理                   | 负荷·风光 DA、残差负荷、日前总发电预报、日历假日、天气预报（应用 **previous-day / 门控前可得** 版本）、MaxBex（若用） |
| **必须滞后**       | 实发、事后量、历史价 → 至少 **滞后 24h**（相对 delivery） | 电价滞后、分电源实发、跨境计划/潮流、不平衡价量                                                   |
| **日频慢变量**      | 用 **前两日收盘（D−2）** 再对齐到小时，避免用到当日未收盘行情     | TTF、EUA、原油、煤、汇率                                                            |


违反上述规则会出现「回测很好、上线不可用」的泄漏。

## 3. 原始数据：需要什么、从哪下载

下列均为 **公开或可免费注册** 的来源。团队自行落盘即可；不必依赖某台机器上的缓存。

### 3.1 ENTSO-E Transparency Platform（主电力数据）

- **入口**：[https://transparency.entsoe.eu/](https://transparency.entsoe.eu/)  
- **API**：需免费注册获取 security token（平台账号申请）。  
- **文档类型速查**（奥地利控制区 / bidding zone 用官方 EIC；查询时按平台当前域编码）：


| 你要的数据           | 典型用途             | 备注                                            |
| --------------- | ---------------- | --------------------------------------------- |
| 日前电价            | 目标变量 + 电价滞后特征    | Day-ahead prices                              |
| 日前负荷预报          | `负荷 DA`、残差负荷     | Day-ahead load forecast                       |
| 日前风光发电预报        | `光伏/风电 DA`       | Wind & solar forecast                         |
| 日前总发电预报         | `日前发电总量预报`       | Generation forecast（总量类文档）                    |
| 分电源实际发电         | 各类 `gen_*_lag24` | Actual generation per type → **特征里必须滞后**      |
| 跨境计划商业交换 / 物理潮流 | 跨境块（筛查后默认不上）     | Scheduled exchanges / physical flows → **滞后** |
| 水库蓄能量           | 水库块（默认不上）        | Water reservoir                               |
| 不平衡价/量          | 不平衡块（默认不上）       | Imbalance → **滞后**                            |
| 发电不可用 / 停机      | 停机块（默认不上）        | Unavailability                                |


**重要缺口**：进入 **Core Flow-Based** 后，奥地利与德国、斯洛伐克之间的 **经典双边日前 NTC**，Transparency 上经常 **无数据**。这不是下载失败，而是平台不再按旧双边 NTC 发布。若需要「容量」类特征，用下一节 JAO MaxBex 作代理（但树模型筛查后 **默认仍不上线**）。

### 3.2 JAO Core Publication Tool（可选：跨境容量代理）

- **入口**：[https://publicationtool.jao.eu/core/](https://publicationtool.jao.eu/core/)  
- **接口思路**：Core API 的 **MaxBex（最大双边交换）**，小时分辨率。  
- **覆盖**：Core 相关边界自约 **2022-06** 起才有稳定序列；更早年份为空。  
- **用途**：文献/机制分析、或基础模型协变量试验；**LGBM 定稿 32 维不含 MaxBex**。

### 3.3 Open-Meteo（天气）

- **入口**：[https://open-meteo.com/](https://open-meteo.com/)  
- **推荐 API**：  
  - Historical Forecast / Previous Runs（门控前可得的预报场），**不要**用「事后分析场」冒充日前可知天气。
- **建议变量（一次拉全，训练再子集）**：  
`temperature_2m`, `relative_humidity_2m`, `cloud_cover`,  
`shortwave_radiation`, `direct_radiation`, `diffuse_radiation`, `direct_normal_irradiance`,  
`wind_speed_10m`, `precipitation`  
（风速单位用 m/s。）  
- **空间**：奥地利若干代表城市取均值即可（代理站点方案）；不必一上来做全国网格。

### 3.4 大宗商品（日频）


| 品种          | 是否进定稿       | 获取方式（任选可靠公开/授权源）       |
| ----------- | ----------- | ---------------------- |
| **TTF 天然气** | **是（唯一保留）** | 欧洲气价日收盘（交易所/行情商/可信聚合源） |
| EUA 碳配额     | 否           | 同上                     |
| Brent / 原油  | 否           | 同上                     |
| API2 煤      | 否           | 同上                     |
| 亨利港气、欧元兑美元等 | 否           | 同上                     |


对齐规则：**D−2 收盘 → 向前填充到 D 日各小时**。  
整包进模型在 2025 外推上会变差；只留 TTF。

### 3.5 奥地利法定假日

- **内容**：联邦法定假日（含复活节关联移动假日）。  
- **获取**：奥地利政府假日表，或标准假日库 / 自建日历（固定日 + 西方复活节算法推导复活周一、升天、圣灵降临周一、圣体节等）。  
- **用法**：二进制 `是否法定假日`，按 delivery 日期对齐。

### 3.6 不建议作为默认数据源的东西


| 数据                      | 原因                                  |
| ----------------------- | ----------------------------------- |
| 付费日内指数 / 逐笔成交           | 付费或非日前主路径                           |
| 电力期货曲线（未经验证）            | 未进入本轮有效特征集                          |
| 邻区价·荷·风光                | 本轮范围外；若加入必须 **重新联合消融**，不能直接堆在 32 维上 |
| 经典 AT↔DE / AT↔SK 日前 NTC | 平台常空；勿空等                            |

## 4. 特征怎么从数据构造

下面按「特征块」说明。中文名为对外名称；括号内为常见程序列名，便于对接代码。

### 4.1 电价滞后（目标的历史）

由 AT 日前电价序列生成：


| 特征                   | 构造         |
| -------------------- | ---------- |
| 电价滞后 24/48/72/168 小时 | 同小时历史价     |
| 昨日均价 / 最高 / 最低 / 波动  | 昨日 24 小时统计 |


### 4.2 日历与假日

由时间戳 + 假日表生成：小时正余弦、星期、是否周末、月份正余弦、是否法定假日。

### 4.3 日前功率


| 特征               | 构造                    |
| ---------------- | --------------------- |
| 日前负荷 / 光伏 / 风电预报 | ENTSO-E DA            |
| **日前残差负荷**       | 负荷 DA − 光伏 DA − 风电 DA |
| 上述各量的 lag24      | 昨日同时刻 DA（形状对照）        |


### 4.4 天气

代表城市均值：气温、10m 风速、短波辐射、云量；（可选）采暖度日、气温日变化。  
**训练用特征必须来自门控前可得预报**，与实况分析场区分开。

### 4.5 分电源实发（一律 lag24）

从「按类型实际发电」构造抽蓄耗电、跨境交易实发、径流/库蓄水电、生物质、地热、其它、垃圾发电、光伏实发、残差负荷实发、可再生占比、抽蓄净出力等，**全部滞后 24 小时**。

### 4.6 日前发电总量预报

门控前可知的系统总发电 DA（非实发）。筛查中信息量很大。

### 4.7 大宗

日频收盘 → D−2 → 对齐小时。定稿 **只保留 TTF 水平**（可再视需要加变化率，但本轮有效结论是「一列 TTF」）。

### 4.8 候选但默认不上线的块（构造方式从略）

跨境计划/潮流 lag24、MaxBex 十条边界、水库水平与周变化、不平衡 lag24、停机不可用 —— 均可从 §3 下载并构造，但 **不要放进默认上线列表**（原因见 §6）。

## 5. 哪些特征有用（定稿 32 维）— 为什么

**评测协议（结论所依据的）**：时间外推；训练窗约 **730 天**；约 **每 7 天重训**；评估 **2025 全年**。  
相对朴素昨同小时价 MAE≈20.8，定稿约 **13.7**。

### 5.1 完整定稿清单


| #     | 中文名                | 列名                                      | 为什么有用（直觉 + 筛查）                           |
| ----- | ------------------ | --------------------------------------- | ---------------------------------------- |
| 1–3   | 电价滞后 24/48/168h    | `price_lag24/48/168`                    | 强自相关与周周期；EPF 骨架，缺了地板都站不住                 |
| 4     | 昨日均价               | `price_d1_mean`                         | 日水平漂移；比再堆更多价统计更稳                         |
| 5–10  | 小时余弦、星期、周末、月正余弦、假日 | `hour_cos`…`is_holiday`                 | **树模型没有长序列归纳偏置**，必须显式给周期与假日              |
| 11    | 日前光伏预报             | `at_solar_da`                           | 可再生压价/抬价的主形状                             |
| 12    | 日前残差负荷             | `at_resload_da`                         | **净需求**，比单独负荷或风更直接                       |
| 13–14 | 负荷/光伏 DA 的 lag24   | `at_load_da_lag24`, `at_solar_da_lag24` | 昨日 DA 形状对照，补一点惯性                         |
| 15–18 | 气温、风、短波、云量         | `wx_*`                                  | 校正风光与需求；短波与光伏互补                          |
| 19–30 | 分电源实发 lag24（12 列）  | `gen_*_lag24` 等                         | 水电/抽蓄/结构惯性；树模型用「昨日机组结构」补序列模型本会从价里挖的信息    |
| 31    | 日前发电总量预报           | `at_gen_da_a71`                         | LOFO 中常居最有价值之一：系统供给侧日前预期                 |
| 32    | TTF 天然气价           | `ttf`                                   | **唯一**从大宗里加回仍降误差的燃料通道（约再降 0.05–0.06 MAE） |


### 5.2 定稿时被剪掉、但同族仍「有用」的说明

- **风电 DA**：在已有残差负荷 + 光伏后，块内 LOFO 常显冗余，故 32 维未单列；信息多进了 `at_resload_da`。  
- **电价 lag72、昨日最高/最低/波动**：与保留的价滞后共线，剪枝后更干净。  
- **小时正弦**：与小时余弦功能重叠，只留余弦足够。

### 5.3 方案阶梯


| 方案            | 约维数    | 2025 滚动 MAE（量级） |
| ------------- | ------ | --------------- |
| 昨同小时价         | 1      | 20.8            |
| 全量候选          | ~98    | 14.4            |
| 核心块           | ~47    | 14.2            |
| 剪枝无气          | 31     | 13.8            |
| **定稿 31+TTF** | **32** | **13.7**        |

## 6. 哪些特征没用（默认不上线）— 为什么

下列均在「已有 31/32 维底座」上做过 **整块去掉 / 整块加回 / 逐列加回**。结论是对 **2025 滚动 MAE** 而言，不是否定其物理意义。


| 特征族                                 | 判定      | 为什么                                        |
| ----------------------------------- | ------- | ------------------------------------------ |
| **大宗除 TTF 外全部**（EUA/Brent/API2/汇率等） | 不上      | 树重要性常很高，但外推消融：**去掉大宗更好**；分布偏移与虚假相关。只留 TTF。 |
| **跨境计划与潮流 lag24**                   | 不上      | 加回整块变差；与价滞后/供需共线；且无邻区价时跨境「半边」信息弱。          |
| **MaxBex（十条边界）**                    | 不上      | 加回变差；Core FB 下双边容量代理对**点预测**偏弱；文献更常与邻区价联用。 |
| **水库蓄能量**                           | 不上      | 变化过慢；径流/库蓄发电 lag 已部分吸收。                    |
| **不平衡价/量 lag24**                    | 不上      | 偏平衡/日内机制；对日前目标是事后噪声。                       |
| **停机不可用**                           | 不上      | 稀疏、脏、与发电预报重叠；全年平均被常态小时冲掉。                  |
| **经典 AT↔DE/SK 日前 NTC**              | 无法作为主特征 | 平台常无发布，不是特征无效而是 **数据不存在**。                 |
| **邻区价荷风光**                          | 本轮不做    | 未进联合消融；要做必须重跑全套筛查。                         |


**一句话**：文献里「有人用」只配进 **候选池**；上线必须过滚动外推 + 消融。Gain ≠ 因果。

## 8. 基础模型补充（TimesFM-3 零样本，勿与 LGBM 混为一谈）

在 **同一类 AT 日前任务** 上，对预训练时序模型（长上下文，如 ctx≈160 天）做协变量选型时，结论与树模型有系统性差别：


| 点            | 树模型（LGBM）        | 长上下文基础模型（ZS）                                      |
| ------------ | ---------------- | ------------------------------------------------- |
| 日历 / 假日      | **要**（无长记忆）      | 往往 **不要**：周期可从价序列学；假日效应被负荷/光伏 DA 代理，全年 MAE 增量过门槛难 |
| 分电源 / 跨境 lag | **要一部分 gen_lag** | 常整组有害（更信日前 DA + 天气）                               |
| MaxBex       | 加回有害 → 不上        | 可能只留 **奥→德** 一条仍有增益                               |
| 天气           | 温风辐射云都留          | 常只留 **短波** 即过门槛                                   |
| 精简核心         | 32 维表特征          | 可到个位数协变量（如：总发电 DA、残差负荷、光伏 DA、短波、奥→德 MaxBex、TTF）   |


**交接原则**：

- 团队若以 **LGBM / 表模型** 交付 → **以本文 §5 / §6 为准**。  
- 若上 **基础模型** → 重新做协变量搜索，**不要直接照搬 32 维，也不要假设「不要日历」适用于树模型**。

## 9. 方法边界（写进交接以免误读）

1. 结论是 **相对排序与可上线子集**，不是「全球最优超参 / 最优模型」。
2. 主评年是 **2025**；换 2026+ 或市场结构大变应重跑筛查。
3. 天气与 MaxBex 存在历史缺口（早期年份可能空），建库时要做覆盖率检查。
4. 「LEAR 辅集」若使用，应是 **更小特征集**，不是把 98 维塞进线性模型。
5. 15 分钟与小时协议的 MAE **不可直接横比**。
