# 11｜计划SOC与双结算账本

## 这一步解决了什么

旧`forward_dual`的说明仍写48小时DA目标，而且没有真正检查DA计划是否满足
SOC约束。现在模型侧合同统一为：在D-1截止时点锁定D日24小时DA计划，交付日
内RT每小时重新预测未来4小时，但只执行第一个动作。

新增的`BESSActionProjection`会把DA意图动作投影成可执行计划，并返回：可执行
动作、充放电量、完整计划SOC轨迹和被裁剪的能量。计划SOC与真实SOC严格分开：

- 计划SOC只检查DA计划，不改变电池的真实状态；
- 真实SOC只由RT实际动作更新；
- 连续日期内两条SOC都跨日传递；遇到被排除的夏令时日或数据缺口时，开启
  新的连续段并明确记录重置次数；
- 每个当地交付日重置当日累计放电上限，SOC本身不按天重置。

`plan_track=True`原来不会产生任何实际效果。现在它会明确抛出
`NotImplementedError`，避免用户误以为已经实现“先跟踪DA再做RT套利”。

## 双结算账本

每小时先将DA计划换成计划净能量，再将RT意图动作按真实SOC、功率和当日放电
上限裁剪成实际净能量。收益分成四项：

1. DA腿：DA价格乘以锁定的DA计划量；
2. RT偏差腿：RT价格乘以“RT实际量减DA计划量”；
3. 退化成本：只对RT实际充放电吞吐扣一次；
4. 可选偏差罚金：默认关闭，只有配置明确启用才计算。

## 小数字验证

测试构造了一个2 MWh电池：第0小时价格10时充1 MWh，第1小时价格30时放
1 MWh。若RT实际动作等于DA计划，RT偏差为0，最终收益严格等于20。另有测试
固定以下行为：不交易收益0、连续过量放电被SOC裁剪、取消DA计划且DA/RT同价时
两条市场腿相互抵消、吞吐成本只扣一次、极小浮点边界误差不会被误判成SOC越界。

夏令时的23小时日不会被伪装成24小时日。该阶段完整项目测试结果为`39 passed`；
加入RT协调对照后的最新结果见文档16。

## 仍需团队确认的边界

当前主回测把DA解释为需要物理可行的计划，因此使用计划SOC投影。这是保守的
模型侧实现，不是老师或市场规则已经确认的最终答案。如果团队最终把`u_DA`
定义成允许独立于电池物理状态的金融头寸，应建立另一套有头寸上限的结算合同，
不能静默关闭计划SOC后继续沿用同一个结果名称。

不同DA模型共享同一RT模型时，实际动作和期末真实SOC完全相同，所以期末库存
对二者的收益差会抵消。本轮没有人为添加期末估值。以后比较不同RT模型时，必须
先统一期末库存清算或终端SOC规则。
