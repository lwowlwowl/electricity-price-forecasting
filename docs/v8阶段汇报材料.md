## 一、做了什么

### 1.1 画了 DA-only 和 RT-only 的框架

按 W11 定的方向（日前和实时拆开、分而治之），把两条路线分别整理了一遍：

- **DA-only（主线）**：只用日前起报时点能拿到的信息（历史日前价、历史负荷、天气预报、日历），只输出未来 24 小时的日前价格曲线，直接生成日前充放电计划。框架图更新在 `docs/model_architecture.drawio`，五条输入流（日前价、实时价、负荷、风光、日历）各自编码后过跨模态融合层再解码输出。
- **RT-only（第二阶段）**：单独定义实时市场的滚动预测窗口和输入信息截止时点，它的定位是"在日前计划基础上做有限修正"，不抢日前计划的主导权。

拆分的理由写在 `docs/todo4.md`：当前版本是日前和实时绑在一个模型里联合训练的，结果变好变坏说不清是谁的功劳，所以要先拆开做干净对照——如果 DA-only 单独就够好，联合建模的复杂度未必值得；如果联合版明显更优，也要能证明收益确实来自实时信息而不是别的混杂因素。

### 1.2 修了之前的一批 bug

对训练、结算、基准这几块代码做了一次排查，确认并修掉了若干问题。挑几个典型的：

**① 实时价格那条预测线没接到"赚钱信号"上（最严重）。**
训练信号在传到实时价格预测头之前被一个多余的 detach 截断了，梯度恒为零——等于模型只被教会了预测实时价格，但从来没被教会"预测得准是为了什么时候放电"。验证方式：关掉预测损失、只留决策损失，看实时预测头的权重梯度，修复前是零，修复后恢复正常。

**② "开天眼最优"基准算虚高了。**
我们有个用真实价格算最优调度的基准（LP Oracle），之前算的时候少扣了违规罚金、也漏了每日放电量上限这两个约束——基准被高估，显得模型比实际差。修完之后基准和模型用的是同一套约束口径。

**③ 账面收益按"想放多少"记账，不是"实际放出多少"。**
电池明明没电了放不出电，但结算时按放电意图记账，SOC 空电的时段账上还挂着收益。修完之后没电就是真没收益。

**④ 日前那条线的决策梯度被缩小了几十倍。**
代理损失里统一除了一个不该除的数，导致日前项的训练信号强度只有设计值的 1/48。验证：修复前后两项梯度的比例正好差 48 倍。

每个 bug 都写了验证方法并跑通，完整清单在 `docs/todo3_2.md`，可以逐条翻。

## 二、发现了什么

修 bug 的过程反过来说明了一件事：**之前实验里"实时预测质量是瓶颈"这个老大难，很可能不是模型能力问题，而是实时那条腿的决策信号从来没真正生效过**（bug ① 和 ④ 叠加的结果）。所以这块的实际水平，得等修完之后的实验重新验证，之前的数字仅供参考。

另外，老师新发的数学建模说明（w12）我对照过了：新规范要求的"只做日前 + LP 求解 + SPO+ 损失"，和我现在这套框架差在决策层和训练信号两块；但五流编码、跨模态融合这套底座是共用的，切换过去不用推倒重来。
