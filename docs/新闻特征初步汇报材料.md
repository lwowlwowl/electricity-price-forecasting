# 新闻情绪/事件特征工程 —— 阶段性汇报

时间范围：2025-01-01 至 2026-06-02
数据源：GDELT GKG v2（能源相关主题粗筛） + 正文抓取 + LLM 结构化特征抽取

---

## 零. 数据源与抓取方式说明

新闻元数据来自 **GDELT GKG v2**（Global Database of Events, Language, and Tone / 全球事件、语言与语气数据库，Global Knowledge Graph 部分），是一个持续监测全球新闻媒体、开放免费下载的公开数据库，官方每 15 分钟发布一次增量文件（http://data.gdeltproject.org/gdeltv2/），一天理论上有 96 个时间切片（00:00, 00:15, 00:30 ... 23:45 UTC），每个切片里包含当时抓取到的全球新闻文章的元数据，字段包括新闻URL、涉及的主题标签（Themes）、语气分数（Tone）、提及的地理位置等，但不包含新闻正文本身。

出于抓取成本和数据量控制的考虑，本项目**没有下载全天 96 个切片**，而是每天只抓取 **12:00 UTC 这一个 15 分钟切片**（脚本里 `SAMPLE_HOUR = "120000"`），作为当天新闻的抽样代表。具体流程是：按天遍历 2025-01-01 至 2026-06-02 共518天，每天下载对应的 12:00 UTC 这一个 GKG 文件，解析后按"是否命中能源相关主题"做粗筛（见下文第三节），再按文章提到的州名映射到 ERCOT/PJM/CAISO/NYISO 四个市场或归入 US_GENERAL，最终得到逐条明细并按市场做日频聚合。

这种"每天抽一个时间点"的做法属于时间维度上的降采样，好处是大幅降低了抓取量和处理成本，代价是可能漏掉发生在当天其他时段、但在 12:00 UTC 之后才被 GDELT 收录或报道的重要新闻事件（例如美国东部时间清晨或深夜发生的事件）。这是当前数据的一个已知设计取舍。

对筛选出的这批新闻 URL，进一步做了去重和正文抓取，具体情况如下。

## 二、LLM 特征抽取试验（100篇小样本）

### 使用模型

DeepSeek 官方 API 的 **deepseek-v4-flash**（DeepSeek 最新一代轻量模型，2026年更新命名），性价比较高，参考价格：输入约 1 元/百万 tokens，输出约 2 元/百万 tokens。

### 抽取维度（Schema，共10个字段）

| 字段 | 含义 |
|---|---|
| markets_llm | LLM 重新判定的关联市场（ERCOT/PJM/CAISO/NYISO/US_GENERAL 子集） |
| event_type | 事件主类型（weather/supply_shock/demand_shock/policy_regulation/fuel_price/market_operation/unrelated） |
| weather_subtype | 天气细分（heatwave/coldwave/storm/hurricane/drought/wildfire/flood/none） |
| fuel_subtype | 燃料价格细分（natural_gas/coal/oil/uranium/carbon/none） |
| sentiment | 情绪极性 [-1, 1] |
| severity | 事件严重度 [0, 1]（与情绪解耦，避免"事件强度"与"情绪倾向"混淆） |
| price_relevance | 电价关联度 [0, 1] |
| confidence | LLM 判断置信度 [0, 1] |
| summary | 一句话摘要（≤40词英文） |
| raw_model | 使用的模型名 |

### 100篇测试结果

- **成功率 100/100，无失败**
- 判定为与电价"相关"（event_type ≠ unrelated）：**22 篇（22%）**；不相关：78 篇（78%）
- 置信度：
  - 相关文章：均值 **0.77**（区间 0.30–0.90）
  - 不相关文章：均值 **0.95**（区间 0.60–1.00）
  - 说明模型对"明显不相关"判断更有把握，对"间接关联"判断相对谨慎，分布合理
- 若用更严格的 `price_relevance > 0.5` 筛选高相关性新闻，100篇里仅 **4篇**达标，均为真正有分量的事件，例如：
  - 爱荷华寒潮推高供暖需求，可能推升电价（price_relevance=0.8）
  - 霍尔木兹海峡局势推高全球油气价格，波及美国能源市场（price_relevance=0.7）
  - 密歇根北部暴风雪导致大范围停电、州进入紧急状态（price_relevance=0.6）
  - 欧盟制裁叠加炼油厂停产推高柴油裂解价差（price_relevance=0.7）

说明模型能识别出真正有信号价值的新闻，而非不加区分地全部标记。

### 成本与耗时

- 100篇总耗时 **88.8 秒**（4线程并发），单篇平均 3.5 秒
- 100篇总成本约 **¥0.22**
- 按此比例换算，全量剩余约 11029 篇文章，预计成本约 **¥25**，耗时约 1–3 小时（视并发数而定）

## 三、为什么抓下来的新闻很多不相关

GDELT 抓取阶段采用的是**关键词/主题标签命中**的粗筛规则，而非语义理解：

1. **主题范围偏宽**：设定的"能源相关主题"集合中，除 `ECON_ENERGY`、`ECON_OILPRICE` 等直接相关主题外，还包含 `ENV_STORM`、`ENV_HURRICANE`、`ENV_HEATWAVE`、`ENV_COLDWAVE`、`ENV_WILDFIRE`、`ENV_FLOOD`、`ENV_DROUGHT`、`ENV_GREEN`、`ENV_CLIMATECHANGE`、`NATURAL_DISASTER` 等天气/环境类主题，理由是极端天气可能间接影响用电负荷和电价。但 GDELT 的主题标注基于关键词词典自动匹配，不做上下文语义判断——只要文章出现 storm、tornado、heatwave 等词汇就会被打标，无论内容是"风暴导致电网负荷激增"还是"开车如何应对暴风天气"这类完全不相关的内容。

2. **地域归属同样基于关键词匹配**：文章只要提到某个州名就会被归入对应市场，不区分上下文（例如一篇讲移民政策的新闻只因提到"德州"就被归入 ERCOT）。

3. **设计取向是"高召回、低精确率"**：目的是尽量不漏掉真正的极端天气/能源事件报道，代价是引入大量表面关键词命中但实际不相关的噪声。这正是需要在其后引入 LLM 做语义层面精确过滤的原因，而不是直接把 GDELT 粗筛结果当作最终新闻协变量使用。

### price_relevance 分布与日期覆盖率（关键，直接影响聚合方案设计）

以全量时间跨度 518 天（2025-01-01 至 2026-06-02）为基准，不同相关性口径下的日期覆盖情况：

| 口径 | 文章数 | 占比 | 覆盖天数 | 覆盖率 | 有新闻的天：平均/中位数篇数 | 完全空白天数 |
|---|---|---|---|---|---|---|
| event_type ≠ unrelated（宽松） | 2103 | 18.9% | 434 / 518 | **83.8%** | 4.85 / 3 | 84 |
| price_relevance > 0.3（中间档） | 867 | 7.8% | 287 / 518 | **55.4%** | 3.02 / 2 | 231 |
| price_relevance > 0.5（严格） | 461 | 4.1% | 177 / 518 | **34.2%** | 2.60 / 2 | 341 |

可以看出，筛选口径越严格，日期覆盖率下降得越快：用"是否相关"这一宽松标准，八成以上的天数能凑到至少一条新闻；但用更严格的 `price_relevance > 0.5` 筛选真正高相关的新闻，518天里有341天（约66%）完全没有任何一篇达标新闻。这说明新闻类协变量本身具有**稀疏、非均匀分布**的特点（不同于温度、负荷等每小时都有观测值的连续协变量），大事件发生时才有报道，平时是空窗期，这是新闻数据的固有属性，不是抽取环节的问题。

这一发现直接影响下一步聚合方案的设计：需要明确决定空白天如何处理——是直接填 0（表示"当天无重大新闻事件"，本身也是一种信息），还是允许有限的前向填充（让重大事件的影响延续 1-2 天，贴近其现实影响的持续性）。初步倾向使用 `price_relevance > 0.3` 作为主力过滤阈值（覆盖率55.4%，信号密度适中），配合空白天填0 + 小幅前向填充的策略，避免 `>0.5` 档过于稀疏导致特征列大部分时间为常数、模型难以学到有效信号。

## 结论

518 天（2025-01-01 至 2026-06-02）里，从 GDELT GKG 按能源相关主题粗筛、去重后共抓到 **28040 篇**新闻，对这 28040 篇逐一抓取正文，最终有可用正文的为 **11129 篇（占比 39.7%）**，其中 11128 篇已完成 LLM 结构化特征抽取（成功率 99.99%），实际花费 ¥25.15，耗时约82分钟；经 LLM 判定与电价真正相关的（event_type ≠ unrelated）合计 **2103 篇（占最初抓到的 28040 篇的 7.5%）**。

## 可能的新方向？—— INFINI-NEWS Corpus（HuggingFace）

调研过程中发现 HuggingFace 上有一个名为 **INFINI-NEWS Corpus**（`ruggsea/infini-news-corpus`，配套官网 infini-news.uni-graz.at）的公开新闻数据集，值得作为后续补充或替代 GDELT 新闻源的一个方向记录下来。

**数据来源与规模**：该数据集基于 Common Crawl 的 CC-News 归档构建，覆盖时间范围为 **2016年8月至今（持续更新，官网显示到2026年4月）**，总量约 **13.5亿篇**新闻文章，是一个多语言、超大规模的新闻语料库，已抽取正文、做过清洗，并标注了语言和主题信息，同时提供毫秒级的全文检索接口（基于 infini-gram-mini 的 FM-index 索引）。

**潜在优点**：规模和时间跨度大（覆盖2016年至今，远超本项目518天），正文已预先抽取清洗好（不再受403/超时等反爬问题困扰），并支持关键词全文检索，理论上筛选效率更高。

**潜在缺点**：仍是通用新闻语料，不是能源专用数据集，需要重新做相关性筛选；完整数据需申请权限（gated），获取流程和配额未知；数据量巨大，存储和检索成本更高；目前仅调研阶段，尚未实测验证质量。

## 附：LLM 系统提示词原文（中文翻译）

你是一名能源市场分析助手。你阅读一篇新闻文章，并提取与美国电力批发市场（ERCOT / PJM / CAISO / NYISO）短期电价预测相关的结构化信号。

请始终返回一个单独的、合法的 JSON 对象，不要加 markdown 代码块标记，不要有多余文字，且必须严格匹配以下 schema：

```
{
  "markets_llm": [<从 ["ERCOT","PJM","CAISO","NYISO","US_GENERAL"] 中选取的子集>],
  "event_type": <取以下之一 "weather","supply_shock","demand_shock","policy_regulation","fuel_price","market_operation","unrelated">,
  "weather_subtype": <取以下之一 "heatwave","coldwave","storm","hurricane","drought","wildfire","flood","none">,
  "fuel_subtype": <取以下之一 "natural_gas","coal","oil","uranium","carbon","none">,
  "sentiment": <[-1,1] 之间的浮点数，负值=看跌电价，正值=看涨电价，0=中性>,
  "severity": <[0,1] 之间的浮点数，0=轻微/无实质影响，1=极端严重事件>,
  "price_relevance": <[0,1] 之间的浮点数，0=与电价无关，1=高度相关>,
  "confidence": <[0,1] 之间的浮点数，表示你对本次判断的置信度>,
  "summary": <一句话摘要，不超过40个词，英文>
}
```

补充说明：

- markets_llm：应根据文章内容（地名、电网运营商、公用事业公司、州名）自行推断，而不是依据任何外部标签。只有在无法识别出具体市场、但内容仍与能源/宏观经济相关时，才使用 "US_GENERAL"。如果文章确实完全无关，此字段可以为空列表。
- event_type 中的 "unrelated" 应当被大量、宽松地使用，凡是与能源、天气驱动的供需、电力市场毫无关系的文章（例如名人新闻、体育新闻、地方治安新闻、恰好被抓取到的讣告等），都应判定为 unrelated。
- weather_subtype 仅在 event_type="weather" 时才有意义，否则填 "none"。
- fuel_subtype 仅在 event_type="fuel_price" 时才有意义，否则填 "none"。请选择文章主要讨论的那种主导燃料。天然气对美国电力市场的价格相关性远高于其他燃料（因为它在许多地区是边际发电机组的燃料）；煤炭/石油/铀的价格传导更慢或更间接。
- severity 衡量的是事件本身在现实世界中的严重程度（例如一次轻微寒潮 vs. 引发电网紧急状态的历史性冬季风暴），与语气/措辞无关。不要将它与 sentiment 混淆：一个严重的事件仍然可能在价格方向上是不确定的。
- price_relevance 对于大多数普通新闻应该给低分（<0.2）；只有那些可能真正影响短期电力批发价格的文章（极端天气预报、电厂停机、电网紧急警报、燃料价格冲击、重大政策变化）才应给高分。
- 请保持简洁和果断，不要在 JSON 字段本身里使用模糊、犹豫的措辞。
